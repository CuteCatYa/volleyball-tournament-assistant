**三层职责边界（关键架构约束）：**

| 层 | 职责 | 是否可出错 |
| --- | --- | --- |
| **确定性引擎**（云函数内纯函数） | 分制/局制/积分、抽签随机数、贝格尔编排、冲突检测、排名 | 不可出错（100% 正确，需单测覆盖） |
| **协议/数据层**（云函数） | 权限校验、状态机、事务、数据读写、PDF 渲染 | 不可出错 |
| **AI 层**（ai-gateway） | 语义解析、文书润色、审核建议话术、客服 RAG 问答 | 可发挥（人工终审 + 降级） |

> 一句话：**比分/排名/积分/赛程由引擎生成，LLM 只碰「表达」。**

## 2. 技术选型

| 层 | 选型 | 说明 | 对应 PRD |
| --- | --- | --- | --- |
| 前端 | **微信小程序原生**（WXML/WXSS/JS） | P0 页面量可控、零构建、依赖少，答辩演示稳；目录按域组织，团队化后可迁 Taro | §9 |
| 后端 | **微信云开发**（云函数+云数据库+云存储） | 免运维/免备案/按量付费；`watch` 实时推送支撑比分直播与抽签围观 | §9 |

| AI | **腾讯混元大模型**（经云函数 ai-gateway 代理）；备选其它合规模型 | 统一封装：提示词模板 + Function Calling(JSON Schema) + 内容安全 + 降级开关 + 缓存 | §9、A1-A9 |

| 文书导出 | 云函数模板渲染 → PDF（打印级）+ 小程序翻页页 | 秩序册/成绩册；长任务队列化异步生成 | §4.6/§4.8 |
| 内容安全 | `security.msgSecCheck` / `mediaCheckAsync` | 队名/公告/照片/AI 生成内容全部过审 | §6 |
| 位置服务 | 腾讯位置服务 | 场馆选点、导航（P1） | §6 |

## 5. 云函数设计

> 统一约定：入参 `{ action, payload }`；返回 `{ code, data, msg }`；云函数内做**二次权限校验**（前端 UI 只做展示，数据安全以后端为准）。

| 云函数 | action 示例 | 职责 | 调用的引擎/AI |
| --- | --- | --- | --- |
| `login` | `getOpenId` / `bindPhone` | 登录态、手机号授权、写 users | — |
| `event` | `create` / `update` / `list` / `detail` / `aiParse` | 赛事 CRUD、建赛向导解析结果落库、状态机推进 | core.rules（合法性/场次容量） + ai-gateway（语义解析） |
| `regulation` | `generate` / `save` / `publish` / `exportPdf` | 规程：规则引擎定条款 + AI 组织语言 + 版本锁定 | core.rules + ai-gateway |
| `register` | `createTeam` / `submit` / `review` / `export` | 两段式报名、预审建议、审核状态机、公示导出 | ai-gateway（预审建议，仅建议） |
| `draw` | `seed` / `run` / `manualAdjust` / `result` | 服务端随机抽签、分档/蛇形、约束检查、留痕锁定 | core.draw + ai-gateway（种子解释） |
| `schedule` | `generate` / `conflictCheck` / `adjust` / `standingsInit` | 排程 + 冲突检测 + 手动调整重算 + 积分榜初始化 | core.schedule |
| `score` | `record` / `result` / `standings` | 赛后比分录入、自动驱动积分榜与排名 | core.standings |
| `document` | `generate` / `status` / `pdf` | 数据汇入 → 模板渲染 → PDF/翻页（异步队列） | ai-gateway（寄语/封面） |
| `notify` | `push` / `batch` | 订阅消息批量下发 + 记录 | —（含内容安全） |
| `ai-gateway` | `chat` / `parse` / `rag` / `moderate` | AI 统一网关：prompt 模板、JSON Schema 校验、内容安全、降级、缓存、配额 | 混元大模型 |

## 6. 核心确定性引擎（core/）

> 全部为**纯函数**，无副作用、无 AI、可离线运行。这是 PRD「引擎事实」的代码载体，配 `node --test` 单测保护正确性。

### 6.1 规则引擎 `rules.js`
- `BALL_TYPES`：硬排/气排/沙排的每局分值（25/21/21）、决胜局（15）、领先判定（2 分）、局制（五局三胜/三局两胜）、技术暂停（8/16 或无）、常用积分。
- `scoreMatch(ballType, sets)`：由各局小分判定胜负与局分，返回胜方与总积分（3:0/3:1 胜 3 分、3:2 胜 2 分负 1 分，各球种可配）。
- `validateSets()`：校验单局分值合法性（先到 N 且领先 2 分等）。

### 6.2 编排 `schedule.js`
- `bergerRoundRobin(n)`：贝格尔单循环轮次编排（固定算法，奇数队补 0 轮空）。
- `groupRoundRobinPlusKnockout(teams, groups, ...)`：分组循环 + 交叉淘汰出对阵。
- `singleElimination(n)`：淘汰赛对阵（缺位轮空）。
- `assignSchedule(...)`：受场地/时段/同单位约束的多约束贪心排程 + 连场间隔优化。
- `detectConflicts(...)`：场地/时间冲突、同队同时两场、连场无休息检测。

### 6.3 抽签 `draw.js`
- `randomDraw(teams, groupCount)`：随机分组（随机数在云函数服务端生成）。
- `seededSnakeDraw(teams, seedLevels, groupCount)`：种子分档 + 蛇形排列。
- `checkSameUnitConstraints(...)`：同单位多队分入不同组（硬约束开关）。

### 6.4 排名 `standings.js`
- `rankStandings(rows, config)`：按 **积分 → 胜负关系 → 得失局比值 → 得失分比值** 顺序排名（PRD §4.8 F8.1 与 §4.0 可配）。
- 处理弃权（0 分 / 0:3）、并列与规范化的最终名次输出。

## 7. AI 网关设计（ai-gateway）

**统一协议：** 所有 LLM 调用必须经 `ai-gateway` 云函数，不允许前端直连模型。

```
输入: { scene: 'A1建赛|A2规程|A3秩序册|A4预审|A5种子|A6编排|A9客服|...', input, context }
  ├─ 黑名单/白名单与配额检查
  ├─ 选择 Prompt 模板（含规则库注入）
  ├─ Function Calling → 严格 JSON Schema 校验（失败自动重试→回落）
  ├─ 内容安全 msgSecCheck（输入 + 输出）
  ├─ 结果缓存（同入参 key 命中即返回）
  └─ 降级：模型不可用时返回模板兜底，绝不阻塞核心办赛流程
输出: { code, data, aiFlag: true, quote?: 来源引用 }
```

**核心约束（PRD §5.2 映射到代码）：**
1. A2 规程：积分/名次条款 = `core.rules` 代码生成，LLM 只组织章节语言；生成内容带 `AI 生成，请人工核对` 标识。
2. A7 战报：比分/队名由数据模板拼接，LLM 只写叙事，杜绝事实性错误。
3. 所有 AI 产出落库 `documents` 时带 `aiFlag`，人工确认后可发布。

## 10. 安全与合规

| 主题 | 方案 |
| --- | --- |
| 权限模型 | 云函数二次校验角色；组织者能力仅限其创建/被授权赛事；记录员（P1）权限下放到场次 |
| 抽签公正 | 随机数在**云函数服务端** `crypto.randomInt` 生成；结果发布锁定；任何修改写 `audit_logs` 并通知 |
| 敏感信息 | 身份证等加密存储，前端脱敏（仅后四位）；`players` 权限最小化 |
| 内容安全 | 队名/公告/照片/AI 生成内容过 msgSecCheck / mediaCheckAsync |
| 隐私合规 | 隐私保护指引声明收集项（手机号/证件/照片）；未成年参赛者信息保护 |
